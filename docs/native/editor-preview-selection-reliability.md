### Scoped paint correction and runtime constraint

`PreviewSelectionVisuals` calls WPF's existing `ITextSelection.UpdateCaretAndHighlight`, reads that selection's native caret visual and calls its `UpdateSelection` geometry method. It uses cached, guarded reflection because WPF exposes no public equivalent for this inactive geometry update; [CaretElement](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Documents/CaretElement.cs) owns the native clipped range geometry, brush and opacity. Creating the caret alone was independently insufficient: the ordinary worker still returned at the missing native-focus-owner gate. Directly updating its geometry is the measured effective correction.

The bridge runs after normal navigation/layout publication in Continuous and Pages, and on inactive preview selection changes so an empty caret or semantic fallback also removes old paint. It does not alter source text, source mapping, native selection endpoints, document formatting, keyboard focus, `IsEnabled`, the WPF thread-local focus owner, the 60 ms timer or the 250 ms gate. The existing four-argument navigation entry point and all zoom/document/view/generation cancellation checks remain intact.

The first corrected hosted run, source `713c7ce`, [41476866464](https://github.com/DouglasNLima/local-docs-studio/actions/runs/41476866464), correctly rejected a paint-position error: both candidate appearances changed only 58 of 580 pixels in the first wrapped-word rectangle, while the expected-invisible baselines changed zero. The candidate had drawn geometry before `ScrollToVerticalOffset`'s queued arrange applied the approximately 18-pixel viewport movement. The full-application pixel gate caught this even though logical/UIA endpoints and the unscrolled isolation probe passed. Navigation now commits that existing scroll layout before refreshing native geometry. No timer, observation budget or performance threshold was increased, and the failed source-labelled run remains part of the record.

**Material implementation limit:** these are internal WPF members in the pinned .NET 10 runtime. Lookups are cached; missing members or expected access/layout invocation failures leave the logical selection intact and report diagnostic unavailability rather than changing focus. Cold screen-pixel regressions gate the supported runtime, including exact source/UIA endpoints and preserved focus/owner state. Future WPF runtime updates require those checks; this does not claim a stable public WPF API contract. The local corrected full-application check used the reported payload's unchanged self-contained WPF `10.0.1326.50504`, in addition to the framework-hosted probe.

## Correction

`DocumentPreview` invalidates pending navigation on document, reading-mode and zoom changes. Navigation captures viewing mode and zoom and checks them again at its deferred publication boundaries. A caller validity predicate lets editor selection synchronisation recheck the generation, current immutable source version, visible Split layout, originating focus and exact source start/length after asynchronous layout/pagination. This also prevents comparing pointers from replaced documents.

The original four-argument navigation entry point is retained; an explicit five-argument overload carries the predicate. Initial extension of the signature exposed `MissingMethodException` in the existing paired shown-shell harness against an older product. The compatibility correction restores that binary contract; the current compiled scheduling harness also passes locally when loaded with the old product DLL. This branch-induced harness failure is separate from the unchanged performance threshold.
