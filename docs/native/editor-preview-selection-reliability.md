### Logical versus visual correlation

The visual probe separately reads AvalonEdit's actual selection, `PreviewSourceMap`'s source round trip, `FlowDocumentReader.Selection`'s native pointer offsets, the preview UIA provider and actual screen pixels within that provider's screen rectangle. It first observes the untouched product, then establishes warm and collapsed references. No screenshot or UIA geometry alone is treated as proof of paint. The source is a tiny first-party synthetic fixture; customer content is never used by this probe or uploaded to CI.

In both reading modes, source `(21, 8)` maps back exactly, native pointer offsets are `23..31`, and the cold UIA range is correct. The cold screen crop is identical to the collapsed reference: **zero changed pixels**. One preview/editor focus round trip preserves those endpoints but produces a visible highlight across the selected screen rectangle. Local 150% display observations report rectangle `94 × 30` physical pixels and **2,820 changed pixels** after focus; absolute screen coordinates are retained in the source-labelled JSON. A repeat selection in the warmed viewer remains painted. The probe reads WPF's private caret-visual field only as optional test evidence; production code never depends on private WPF APIs.

This is a confirmed logical-versus-painted discrepancy in a controlled cold reader. It is not proof of dropped input, wrong source offsets, stale preview selection, a timer race or a cancellation defect. It also does not prove the original intermittent report has been reproduced. Microsoft's [TextSelection implementation](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Documents/TextSelection.cs) separates caret/highlight activation from the logical range; that source is supporting context, not a substitute for the measured runtime observations. The exact public-API correction remains an investigation task.

The same compiled hosted probe independently repeats the discrepancy against the [candidate](evidence/selection-sync/visual-hosted-candidate.json) and the prior diagnostic [baseline](evidence/selection-sync/visual-hosted-baseline.json). At the hosted display scale, the selected screen rectangle is `62 × 20`: zero cold changed pixels, then 1,240 changed pixels after the focus round trip. WPF's caret visual is absent cold and present warm in both modes/products; logical endpoints remain identical. These observations support highlight activation as the mechanism of this reproducible synthetic symptom. They do not establish the original customer's cause, and no focus or enable/disable workaround is shipped.

## Correction

`DocumentPreview` invalidates pending navigation on document, reading-mode and zoom changes. Navigation captures viewing mode and zoom and checks them again at its deferred publication boundaries. A caller validity predicate lets editor selection synchronisation recheck the generation, current immutable source version, visible Split layout, originating focus and exact source start/length after asynchronous layout/pagination. This also prevents comparing pointers from replaced documents.

The original four-argument navigation entry point is retained; an explicit five-argument overload carries the predicate. Initial extension of the signature exposed `MissingMethodException` in the existing paired shown-shell harness against an older product. The compatibility correction restores that binary contract; the current compiled scheduling harness also passes locally when loaded with the old product DLL. This branch-induced harness failure is separate from the unchanged performance threshold.

No source-map search or debounce increase is introduced. The synchronisation timer remains 60 ms. Preview-to-editor mapping and its navigation are unchanged.

## Semantic fallback contract

Exact selections use literal source positions, including UTF-16 Unicode positions, LF/CRLF offsets and mapped endpoints spanning multiple formatted inlines. Formatting and other source gaps inside a selection retain their real rendered content; source endpoints which cannot be represented literally do not acquire invented character positions.

For syntax-only selections or unmappable transformed endpoints, collapse the preceding literal highlight, navigate to the parser's semantic source block and show its block indicator with `Selection synchronised as a preview block.` The block is the existing source anchor at or immediately preceding the source offset; it does not claim exact word correspondence. If no block exists, clear the indicator and report `This source selection has no rendered text.` An empty editor caret with no literal endpoint also collapses stale text highlighting. There is no matching-word substitution.
