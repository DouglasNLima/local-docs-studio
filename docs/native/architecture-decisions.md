# Native architecture decisions

Word picture descriptions are read from the individual inline or floating drawing, then its picture metadata, with titles and the existing generic label as fallbacks. Explicit empty descriptions remain empty. Line separators become spaces and Markdown metacharacters are escaped, so untrusted metadata remains literal alternative text. Image bytes can be shared while occurrence descriptions remain distinct. Twelve core regressions and a real, decodable PNG export/reimport fixture pass locally; hosted file-picker, cancellation, warning and preview checks are pending.

Details expansion keeps WPF Expander and ToggleButton controls with the existing template and automation patterns. A fixed application-owned XAML string is parsed once per WPF thread, replacing per-control `InitializeComponent` pack-resource loading in the phase implicated by the timing trace. The cache is thread-local because templates have dispatcher affinity; no document text reaches XamlReader. Dimensions, foreground binding, expansion binding and chevron geometry remain identical. The change avoids that resource lookup but does not establish the cause of the intermittent delay. Existing input bounds remain unchanged. Native pattern/visual checks pass locally; both 2af4471 hosted runs verify Space expansion/collapse, retained focus and unchanged source in all four application contexts each.

Word numbering resolution is separate from Markdown list emission. Cached, bounded paragraph/default-style chains provide numbering identifiers and indentation; direct properties override inherited values, including explicit zero suppression. Paragraph-style `ilvl` is ignored in favour of the numbering definition's `pStyle` association. Linked numbering styles resolve the underlying definition while preserving instance overrides and style associations. Missing associations/targets use explicit notes; cycles and excessive numbering links are rejected. Shared abstract-level caching avoids repeated scans across instances. Word break elements reimport as LF; validation compares exact code after that line-boundary conversion without changing the original source.

Word import resolves recognised paragraph semantics through a cached, bounded style chain, including default styles and explicit outline overrides. Code runs retain literal text, tabs and breaks without Markdown emphasis or hyperlink syntax; referenced bookmarks are emitted outside fences. Consecutive quote paragraphs share a Markdown quote within the same list indentation. Generic spacing/font appearance is not treated as code evidence. Table-cell blocks and code-styled pictures use explicit fallbacks with notes, preserving visible content and image bytes. Code language and nested quote structure are not inferred from Word styles.

Word list items now own one pending native numbering entry. Every emitted paragraph uses the item scope, including headings, code, diagram/formula images, semantic labels and empty items. Continuations explicitly set `w:numId=0` to suppress numbering inherited from template styles while retaining the item's indentation; nested lists own independent numbering instances. Table-first and nested-only items receive an anchor kept with the next block. Available widths constrain inline image extents, table grids and cells, including direct template cell margins; original media bytes and style definitions remain unchanged. Code allocation preflight reserves the additional list properties before package/template construction. Package semantics are tested separately from unverified Microsoft Word pagination and wide-marker layout.

PDF list items own a pending marker shared by their child blocks. The first emitted paragraph consumes it; subsequent paragraphs retain the same left indent without repeating it, while nested lists receive a separate item scope. Marker widths are measured in the actual marker font, preserving zero-based and wide ordered values. Hanging indents and tab stops align wrapped text. Table-first and nested-only items receive a marker anchor kept with the following block; images and table columns use the remaining item/cell width. Unreadably deep nesting fails before destination commit. This preserves selectable text and visual hierarchy without claiming tagged PDF list accessibility.

Installer validation now requires the running application's coreclr.dll and wpfgfx_cor3.dll modules to resolve to its installation directory. The requirement is an explicit validation argument, independent of package metadata. A process snapshot after editor/diagram readiness records actual paths and executable identity before asserting, while the normal framework-dependent build records its runtime without the bundled-path requirement. This distinguishes loaded runtime evidence from merely finding runtime files in a ZIP; it does not certify SDK-free clean Windows.

Diagram-copy validation uses the app's actual Copy image button and a separate process reading the Windows bitmap representation. The expected full-resolution pixels are prepared independently from exact source and the visible resolved palette; two zoom scales must not change clipboard resolution. The check waits for the zoom window to disappear before checking clipboard persistence. It retains the existing production clipboard implementation and makes no claim about untested external paste destinations.

Word code export has a separate expanded-object budget: at most 65,536 code elements across all nested blocks, including paragraph/run formatting, text, tabs and breaks. Preflight precedes template preparation or package creation; compressed-output limits cannot bound the in-memory DOM. Preflight and writing share delimiter enumeration, retaining CRLF semantics across syntax-colour boundaries. Mermaid and formula raster branches do not consume this budget. Excess is a recoverable IOException before destination commit. This addresses the concrete tab-amplification path identified by the cf436b0 review; it is not a general memory bound for every Word structure.

All physical desktop/Office validation modes and Test-NativeInstaller.ps1 require GitHub-hosted Windows markers before arguments, paths or state are processed. These checks prevent accidental developer-machine execution; environment markers are operational guards, not an authorisation boundary. Windowless validation remains available locally. All six refusal cases pass without inventing hosted environment variables.

Opt-in preview diagnostics now bracket component initialisation and record thread CPU, current-thread allocations and GC counts in the bounded validation listener. Production phase events remain content-free and inactive without a listener. CPU counters supply coarse context across the traced interval, including other dispatcher work; the wall-clock input deadline remains authoritative. No warm-up, test reordering, timeout relaxation or control redesign is introduced.

Installer files-in-use evidence uses the actual installed executable and private fixture state, preserving the production [Inno AppMutex contract](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm). The test does not manufacture a mutex or add an application hook. It verifies Setup ownership through a read-only Windows parent-process snapshot before interacting with the blocking dialogue, then compares source, recovery and installation state before/during/after cancellation. The public command retains its disposable hosted-Windows guard; no local desktop interaction is required to build or inspect this check.

Collapsible details keep their body in a single native Section, populated cooperatively before attachment. Expanding/collapsing moves that section once while retaining its inherited font and foreground values. This preserves selectable text, existing source elements and nested controls while avoiding one document mutation per child and typography changes on detachment. An initially expanded body is attached empty before population, retaining the existing construction budget. The initial toggle-construction delay remains a separate investigation.

Source jumps use a zero-length editor selection at the target, preserving navigation history while clearing any old range. Updating AvalonEdit's caret alone retains selection; actual CI demonstrated that the next character then replaced that old range. This applies to diagram recovery, outline/source targets and double-click source navigation. The unchanged actual keyboard regression passes in all four desktop contexts of both df281c0 native runs.

Failed diagram previews retain accessible native Copy source and Edit source actions. The renderer supplies the fence's source offset; the window validates the active document and exact preview snapshot before navigating. Preview-only layout becomes Split so keyboard input reaches the original source. Copy uses the existing diagram-source path, and unavailable native drawings expose no image export actions. Standalone Mermaid and DevOps containers retain their existing source mapping; nothing rewrites the document or changes update trust.

Preview construction exposes disabled-by-default EventSource phase markers for diagnosing intermittent dispatcher delays. A bounded validation listener records phase names, source offsets and elapsed times, without document text or persistent telemetry. Nested-layout checks sample throughout construction so yielding once at the start cannot hide a later long pause. Rendering order, cancellation behaviour and the 250 ms acceptance limit remain unchanged.

Diagram appearance is a bounded choice in PreviewPreferences, independently persisted from application appearance. Core resolves Auto to the existing Lens/Dark palettes and keys its bounded cache by source plus resolved palette. Preview and export callers capture that resolved choice before asynchronous work; Docs Site page appearance cannot override the selected diagram palette. Rendering remains Mermaider/SVG/WPF. Settings transfer 1.2 adds diagramTheme and retains 1.0/1.1 imports, preserving missing choices; earlier native state defaults to Auto. No theme imports, external styles or browser runtime are introduced.

WPF text containers are attached empty to the private document before their descendants are populated. Moving a fully populated paragraph, section, list item or table cell into its final text container otherwise repeats synchronous work after cooperative construction. Nested spans and hyperlinks follow the same parent-first order. Heading properties are set before content insertion. The current displayed preview is replaced only after the complete result returns; cancelled partial documents remain private. Closed details retain detached children, so this change does not certify later expansion latency.

Update checks, downloads and final verification retain their selected environment across awaits. Changing channel cancels the active operation even when the user immediately switches back; a late result must still match the exact selected candidate/download before the UI or installation callback receives it. Core also checks cancellation after installer trust completes so external completion cannot override user cancellation. The view model accepts a composed UpdateService for isolated integration checks; its default composition still owns its transport and uses embedded trust plus Windows verification. No imported settings or release metadata can select that dependency or populate production trust.

The shared WPF construction budget now applies inside inline trees and coloured-code runs as well as between blocks. Paragraphs, headings, nested emphasis and hyperlink labels can otherwise monopolise the dispatcher despite a small top-level block count. Recursive ValueTask construction retains dispatcher ownership and yields at the existing 32-unit/eight-millisecond checkpoints; pending input can cancel the incomplete result. The previous complete preview remains displayed. Synchronous rendering retains its existing non-yielding path. Code colours reuse the validated Core run enumeration, preserving plain-text/high-contrast fallback and exact text.

Session JSON keeps schema 1 and its existing atomic current/backup files. Streaming replaces whole-session byte/string buffers; one shared 512 MiB budget applies to actual encoded bytes on write and the opened write-denying handle on read. A smaller host budget is supported for constrained use and bounded regression fixtures. Oversized writes discard staging without rotating recovery. Oversized or malformed legacy state is copied independently before fallback; failed reads/copies block writes until a successful retry. A single gate serialises reads and writes, and JSON conversion/durable flushing run on a worker. This avoids introducing a second recovery format or a separate chunk lifecycle. The budget includes current text, saved baselines, JSON escapes and metadata; exceeding it is an explicit recoverable failure, not a promise of unlimited open documents.

Package signing is an optional adapter boundary: an existing certificate-store signer or an explicitly provisioned local PowerShell service adapter. Both require a reviewed publisher subject and certificate SHA-256, verified independently against the signed apphost and installer with Windows Authenticode and a timestamp certificate. Providers run as bounded hidden child processes with literal arguments; success alone cannot establish trust. Unsigned mode is the current confirmed configuration and never invokes a provider. Package configuration cannot populate embedded updater trust or enable unsigned execution.

Interrupted-save certification uses a separately owned native process and unique fixture/state paths on disposable Windows CI. The harness terminates the process while the save-error dialogue remains open, preventing normal shutdown from creating the recovery state under test; restart must consume existing bytes before an explicit retry. No production test hook is added. This covers process termination after a rejected save, not interrupted physical writes or power loss.

Save persists the UI-owned session before asset transfer and source commit. The source write journal cannot cover a destination that rejects the initial write handle, and the periodic recovery timer may not have captured recent edits. If independent recovery cannot be written, Save leaves source and the dirty editor unchanged. Four native model checks cover the reproduced locked-source gap, reconstruction, exact retry and recovery failure; they do not claim an actual process-crash test.

Installer continuity validation distinguishes package replacement from application state consumption. After exact preservation checks, a guarded MTA client opens the installed executable with the original state directory, checks all tab text and native settings, then verifies semantic session/preferences continuity and unchanged other state/source hashes. Normal shutdown may update viewport/window positions and rotate session/preference backups; only after those assertions is the lifecycle hash baseline advanced. Existing full UI workflows remain separate. This is same-revision preview continuity, not historical-schema or production-signing certification.

Paged navigation uses the resolved TextPointer page and never follows it with a parent-paragraph BringIntoView. A single 352 KB paragraph demonstrated that the parent request returns to page 1 even when the correct final range is selected. Continuous scrolling retains its separate position-based adjustment. Six bounded block fixtures validate exact final-page visibility and unchanged content, and the existing stale-request/media/navigation checks still pass.

The visible installer check runs on a separate MTA automation thread and only on disposable GitHub-hosted Windows runners. It refuses existing native registration, associations, shortcuts or default installation files, uses a unique reviewed destination, validates native UIA/MSAA choice states and keyboard actions, and cleans up only its own exact uninstaller. It complements the existing silent upgrade/lifecycle checks. No local foreground interaction is required to compile it or verify its execution guard. The first actual runs exposed an obsolete arrow suffix in the test button lookup; the corrected lookup matches Inno 6.7.1 and older labels. All four wizard outcomes pass in both 2c16d47 native runs. The confirmation test observes Yes keyboard focus and uses Space because Enter otherwise activated the default No response.

The PDF-decoration and Find-focus implementations pass both completed b1b500c native runs, including 58 workflows in every application context. The first PR attempt fails an existing layout assertion and remains recorded; no timing threshold was relaxed. The follow-up CI artefact selection retains installed-app highlight reports/screenshots and decorated PDF outputs.

PDF strike-through and highlighting use the native layout engine's generated link rectangles to preserve exact wrapping and pagination. Per-export temporary targets map to bounded decoration records; one pass over the bounded, freshly generated PDF adds strokes and neutral multiply-blended highlight rectangles, removes temporary annotations/objects and restores real URI/bookmark links. The existing supplementary-character mapping correction shares that pass. No browser, private library API, source mutation or PDF-input processing is introduced.

Find has a separate native focus scope so the preview retains logical focus while the query accepts keyboard input. The reader enables inactive selection and uses the theme accent for selection. The desktop regression compares actual pixels inside the selected text rectangle with a collapsed selection while verifying that keyboard focus stays in Find. An unfocused hidden HWND cannot establish this visual result because WPF selection painting depends on its thread's focused text selection.

The page counter is a native Label with content bound to its accessible name. WPF's TextBlockAutomationPeer deliberately excludes TextBlocks inside a ControlTemplate from control view; both 640b999 desktop runs exposed that omission. Both corrected f981943 native runs pass all 57 workflows in built/installed/upgraded/reinstalled apps. The reader's text adapter and page counter have separate focused automation assertions. The [framework implementation](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Automation/Peers/TextBlockAutomationPeer.cs) documents this behaviour.

The preview now uses a native FlowDocumentReader with Automatic, Continuous and Pages preferences. Automatic selects pages at 256 Ki characters or 1,000 mapped source elements. Background pagination bounds initial visible layout; asynchronous page-number resolution uses unique request tokens and ignores superseded requests, changed selections and replaced documents. The public native document automation peer supplies the existing TextPattern on the preview in both modes. Images fit the available page body; diagram panels retain original vector/source callbacks inside bounded native scrolling containers. Returning to Continuous restores original media limits. These choices affect reading only, not source or exported pagination. Settings transfer 1.1 includes reading mode; 1.0 browser/native imports remain accepted and preserve that omitted choice.

The PDF font/mapping implementation is validated in both 230852b native runs, including actual Export-menu use before and after installation, upgrade and reinstallation. Exact artefacts and remaining boundaries are recorded in the [engineering handover](engineering-handover.md).

PDF font fallback checks installed WPF glyph maps and PDFsharp font resolution before selecting a family; a final render event rejects any actual glyph index zero. It preserves inherited formatting and code colours and limits text-run expansion. PDFsharp 6.2.4's [ToUnicode writer](https://github.com/empira/PDFsharp/blob/v6.2.4/src/foundation/src/PDFsharp/src/PdfSharp/Pdf.Advanced/PdfToUnicodeMap.cs) emits supplementary code points as five/six hexadecimal digits instead of UTF-16BE pairs. Only freshly generated, bounded PDFs containing supplementary text are reopened through public APIs; the exact malformed singleton CMap ranges are corrected and the result is saved through the same byte/cancellation limit. Other PDFs avoid this extra pass. No reflection, dependency patch, font download or source substitution is used. Complex-script shaping and bidirectional layout remain outside this correction.

Checked Windows font fallback and a final PDF glyph guard now prevent missing-character boxes. Six local PDF outcomes pass, including actual selectable emoji across formatting, code, tables and links; unsupported characters fail explicitly. Corrected emoji/CJK/combined pages were rasterised and inspected. Source remains unchanged. Complex-script shaping, bidirectional layout and joined/colour emoji remain separate fidelity limits.

The authorised reconstruction uses .NET 10, WPF, CommunityToolkit.Mvvm and AvalonEdit. Domain/parsing/filesystem/state/export/update services live in Core; Windows controls and integrations live in Native; unit and actual Windows validation remain separate projects. The browser product and legacy WinUI/WebView2 shell retain their own code, deployment and identities. No embedded browser, JavaScript runtime or local server is used by the native editor/preview.

Markdown remains authoritative, portable UTF-8 source. Source-aware Markdig nodes provide exact positions for editing, links, review and preview navigation. Edits use pure plans, AvalonEdit anchors and one undo group; asynchronous insertion verifies that the captured document/selection still applies. Native FlowDocument elements retain selectable text and source mapping. Unsupported active/raw HTML is never executed; supported passive figures, labels, anchors, details and progress become typed nodes. Unsupported forms retain source with explicit feedback.

Mermaid uses Mermaider and a bounded native SVG adapter. SVG is checked for active elements, external references and CSS escapes before native conversion. The adapter materialises an opaque declared background and corrects inherited node-label contrast on single solid fills while preserving explicit text colours. Message-bound standalone sequence activation commands become the pinned renderer's shorthand; saved source stays unchanged and unrepresentable commands produce an explicit error. The [compatibility report](diagram-compatibility.md) records tested forms and limits. Raster files are workspace-bounded, byte/pixel-limited and decoded on a serial cancellable STA worker. Frozen drawings/pixels cross to the UI thread; content hashes detect changes even with unchanged timestamps. Caches are bounded and never retain entire document trees. Formula preparation uses native bundled fonts/drawings, keeps exact LaTeX for copy/search and supplies high-resolution export images. Compatibility is measured against retained corpora, not inferred from syntactically valid SVG.

WPF construction shares approximately 8 ms/32-unit dispatcher batches across top-level and nested blocks, including list items and table cells. Cancellation keeps obsolete results from replacing the preview. Immutable shared brushes are frozen. Continuous layout is still synchronous; a measured 128-item list-group experiment offered no useful improvement and was removed. Automatic pagination now avoids laying out the entire long document before showing its first page. Individual page/block layout remains synchronous, and broader performance certification remains open. Editor-only layout parses current headings but skips hidden diagram/syntax/raster/maths/document preparation. Showing preview queues current rendering. Explicit text copying checks current document identity/source and clipboard sequence; single-pane Find targets the visible control.

Native navigation resolves relative paths inside the authorised workspace, including current unsaved target headings. Wiki links retain aliases and distinguish exact paths, ambiguous short names, missing targets and unchecked scans. Reviewed moves update exact ordinary/wiki URL spans, not unrelated Markdown. Source-position scrolling reveals hidden details before deferring to actual WPF layout; stale document requests are ignored. Back/Forward records document identity/path, caret and viewport. Window placement uses Windows APIs; Fluent resources and system high-contrast colours avoid a separate UI framework.

The native status bar uses one stretched grid item so flexible status text yields space to the preview state, caret and Cancel action. Full status remains available through its tooltip. Find/Replace uses native wrapping layout to keep every action reachable at minimum widths. Hidden-shell validation loads application Fluent resources before constructing MainWindow, matching production style resolution; scaled raster checks remain distinct from physical DPI certification.

Editor navigation also accounts for wrapped virtual-line height estimates. A shared bounded deferred service scrolls to the exact line/column, measures the resulting viewport position and retries after layout. Per-editor request revisions, document identity/version and captured selection/caret prevent stale requests from moving newer content. It never edits source. Source history records the resulting viewport; search, review and map use the same service. Both b45246e native CI runs validate actual distant selection after keyboard search. Performance evidence separates warm filesystem/parser/native-layout observations from actual OS input/UIA workflow timing and records memory without forcing collection; timings include the observation mechanism and do not imply a universal response threshold.

Filesystem operations guard source fingerprints and path/reparse boundaries. Safe writes retain a durable intended-content record; external modifications require conflict handling. Reviewed file/folder moves retain original/planned text, check complete bounded inventories and reverse only unchanged completed work. Case-only moves distinguish the source alias from a genuinely occupied destination. Binary assets and empty folders survive folder moves. Private state is excluded. Recovery journals are imported as text drafts; their recorded paths never authorise replay. Successfully saved recovery sessions may archive reviewed journals without deleting them.

Deletion retains saved and unsaved snapshots before using a unique sibling holding directory and Windows recycling. The exact moved file is checked before recycling; failure/cancellation restores it without replacing an external file. Interrupted holding files remain visible. Snapshot recovery opens a new draft and requires an explicit destination. Missing images produce warnings without suppressing text recovery. Automatic pruning is deferred to preserve recoverable data.

Unsaved-document images live in private per-document draft folders referenced by recovery. Image bytes must be validated and persisted before source insertion. Save as rebases/copies portable assets before committing Markdown and cleans up only completed, unchanged failed-operation copies. Explicit URL insertion alone may retrieve bounded HTTPS image content; preview and metadata never trigger network fetches. Asset audits count documented references/current drafts; incomplete scans block removal and unsupported HTML references require manual updates.

HTML import and formatted paste share an inert converter. Images are validated/persisted before replacing a captured selection. Merged spreadsheet cells use bounded expansion with a visible warning. Rich clipboard HTML takes priority over a fallback bitmap; literal paste preserves source. Rendered copy uses Windows CF_HTML with [UTF-8 byte offsets](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format), Unicode fallback and embedded supported pixels. Fixed Excel string metadata protects literal identifiers/formula-like text. Preparation is bounded/cancellable and refuses an intervening clipboard update. Selected-table actions revalidate source identity and isolate only that table; CSV retains exact text/quoting rather than guessing spreadsheet types.

DOCX exports use Open XML SDK and fresh validated packages. Template import keeps supported reusable styles, numbering, headers/footers and referenced media while excluding original body/unrelated metadata. A private library supports selection, rename, reversible archive/restore and prepared-format copies. PDF is generated locally through PDFsharp/MigraDoc; its documented semantic/fidelity limits remain visible. HTML/Docs Site/Markdown bundles are independent exports with guarded destination writes. Exported sites are static and support disk hosting, source metadata, native-rendered assets, section search and relative navigation. Export never deploys a site.

ZIP extraction uses staging, path/reparse protection, actual-byte limits and checksums before publishing a workspace. Exports refuse incomplete scans and omit private state. Optional artefact metadata is strict, bounded, display-only import context: supplied evidence labels never become inferred findings. Context clears on workspace change/restart. Generic bundles omit the manifest; only explicit review-pack export rebuilds safe metadata from included current content. Docs Site front matter takes priority over optional artefact hints.

Private content libraries merge supported browser JSON without replacing originals; templates open new tabs, snippets preserve one Undo and export profiles remain session choices. Browser Word migration exports original DOCX bytes for native validation/import. Appearance transfer uses a separate strict 64 KB JSON contract, bounded depth, duplicate/null/value rejection and optional-field merging. Imports populate private dialogue choices; Apply merges into current preferences without replacing paths or update consent. No browser-profile scanning or imported resource/font loading is introduced. See the [settings contract](settings-transfer-format.md).

Per-user self-contained Inno packaging uses distinct installation, state, mutex, uninstall and Open with identities. Uninstall preserves workspaces/state, default file associations are untouched and files-in-use handling does not force-close unsaved work. Package versions are immutable output directories. See [Inno AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm) and [non-administrative installation](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm).

Installer CI uses two preview versions from one source revision to exercise package replacement. Save dialogue automation separately waits for the labelled enabled filename control within the existing deadline; window discovery alone does not establish child-control readiness. Update checking and installation are separate user-controlled operations. Eligible GitHub metadata must match product, channel, version, architecture, Windows compatibility and official asset location. Validation combines deterministic Core tests, real files/packages, native hidden-control/HWND checks, Windows UIA workflows and installer lifecycle runs. Frozen bitmap clones preserve cross-thread pixels. The earlier combined STA client is a plausible source of the retained timeout, not a proven diagnosis. Failure screenshots/native stacks bypass UIA; no full heap/environment dump is requested. Existing assertions remain unchanged.

Import/export budgets count retained and expanded resources separately.
