# Native architecture decisions

The authorised reconstruction uses .NET 10, WPF, CommunityToolkit.Mvvm and AvalonEdit. Domain/parsing/filesystem/state/export/update services live in Core; Windows controls and integrations live in Native; unit and actual Windows validation remain separate projects. The browser product and legacy WinUI/WebView2 shell retain their own code, deployment and identities. No embedded browser, JavaScript runtime or local server is used by the native editor/preview.

Markdown remains authoritative, portable UTF-8 source. Source-aware Markdig nodes provide exact positions for editing, links, review and preview navigation. Edits use pure plans, AvalonEdit anchors and one undo group; asynchronous insertion verifies that the captured document/selection still applies. Native FlowDocument elements retain selectable text and source mapping. Unsupported active/raw HTML is never executed; supported passive figures, labels, anchors, details and progress become typed nodes. Unsupported forms retain source with explicit feedback.

Mermaid uses Mermaider and a bounded native SVG adapter. SVG is checked for active elements, external references and CSS escapes before native conversion. The adapter materialises an opaque declared background and corrects inherited node-label contrast on single solid fills while preserving explicit text colours. Message-bound standalone sequence activation commands become the pinned renderer's shorthand; saved source stays unchanged and unrepresentable commands produce an explicit error. The [compatibility report](diagram-compatibility.md) records tested forms and limits. Raster files are workspace-bounded, byte/pixel-limited and decoded on a serial cancellable STA worker. Frozen drawings/pixels cross to the UI thread; content hashes detect changes even with unchanged timestamps. Caches are bounded and never retain entire document trees. Formula preparation uses native bundled fonts/drawings, keeps exact LaTeX for copy/search and supplies high-resolution export images. Compatibility is measured against retained corpora, not inferred from syntactically valid SVG.

WPF construction shares approximately 8 ms/32-unit dispatcher batches across top-level and nested blocks, including list items and table cells. Cancellation keeps obsolete results from replacing the preview. Immutable shared brushes are frozen. Final viewer layout is still synchronous; a measured 128-item list-group experiment offered no useful improvement and was removed. Editor-only layout parses current headings but skips hidden diagram/syntax/raster/maths/document preparation. Showing preview queues current rendering. Explicit text copying checks current document identity/source and clipboard sequence; single-pane Find targets the visible control.

Native navigation resolves relative paths inside the authorised workspace, including current unsaved target headings. Wiki links retain aliases and distinguish exact paths, ambiguous short names, missing targets and unchecked scans. Reviewed moves update exact ordinary/wiki URL spans, not unrelated Markdown. Source-position scrolling reveals hidden details before deferring to actual WPF layout; stale document requests are ignored. Back/Forward records document identity/path, caret and viewport. Window placement uses Windows APIs; Fluent resources and system high-contrast colours avoid a separate UI framework.

The native status bar uses one stretched grid item so flexible status text yields space to the preview state, caret and Cancel action. Full status remains available through its tooltip. Find/Replace uses native wrapping layout to keep every action reachable at minimum widths. Hidden-shell validation loads application Fluent resources before constructing MainWindow, matching production style resolution; scaled raster checks remain distinct from physical DPI certification.

Editor navigation also accounts for wrapped virtual-line height estimates. A shared bounded deferred service scrolls to the exact line/column, measures the resulting viewport position and retries after layout. Per-editor request revisions, document identity/version and captured selection/caret prevent stale requests from moving newer content. It never edits source. Source history records the resulting viewport; search, review and map use the same service. Both b45246e native CI runs validate actual distant selection after keyboard search. Performance evidence separates warm filesystem/parser/native-layout observations from actual OS input/UIA workflow timing and records memory without forcing collection; timings include the observation mechanism and do not imply a universal response threshold.

Filesystem operations guard source fingerprints and path/reparse boundaries. Safe writes retain a durable intended-content record; external modifications require conflict handling. Reviewed file/folder moves retain original/planned text, check complete bounded inventories and reverse only unchanged completed work. Case-only moves distinguish the source alias from a genuinely occupied destination. Binary assets and empty folders survive folder moves. Private state is excluded. Recovery journals are imported as text drafts; their recorded paths never authorise replay. Successfully saved recovery sessions may archive reviewed journals without deleting them.

Deletion retains saved and unsaved snapshots before using a unique sibling holding directory and Windows recycling. The exact moved file is checked before recycling; failure/cancellation restores it without replacing an external file. Interrupted holding files remain visible. Snapshot recovery opens a new draft and requires an explicit destination. Missing images produce warnings without suppressing text recovery. Automatic pruning is deferred to preserve recoverable data.

Unsaved-document images live in private per-document draft folders referenced by recovery. Image bytes must be validated and persisted before source insertion. Save as rebases/copies portable assets before committing Markdown and cleans up only completed, unchanged failed-operation copies. Explicit URL insertion alone may retrieve bounded HTTPS image content; preview and metadata never trigger network fetches. Asset audits count documented references/current drafts; incomplete scans block removal and unsupported HTML references require manual updates.

HTML import and formatted paste share an inert converter. Images are validated/persisted before replacing a captured selection. Merged spreadsheet cells use bounded expansion with a visible warning. Rich clipboard HTML takes priority over a fallback bitmap; literal paste preserves source. Rendered copy uses Windows CF_HTML with [UTF-8 byte offsets](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format), Unicode fallback and embedded supported pixels. Fixed Excel string metadata protects literal identifiers/formula-like text. Preparation is bounded/cancellable and refuses an intervening clipboard update. Selected-table actions revalidate source identity and isolate only that table; CSV retains exact text/quoting rather than guessing spreadsheet types.

DOCX exports use Open XML SDK and fresh validated packages. Template import keeps supported reusable styles, numbering, headers/footers and referenced media while excluding original body/unrelated metadata. A private library supports selection, rename, reversible archive/restore and prepared-format copies. PDF is generated locally through PDFsharp/MigraDoc; its documented semantic/fidelity limits remain visible. HTML/Docs Site/Markdown bundles are independent exports with guarded destination writes. Exported sites are static and support disk hosting, source metadata, native-rendered assets, section search and relative navigation. Export never deploys a site.

ZIP extraction uses staging, path/reparse protection, actual-byte limits and checksums before publishing a workspace. Exports refuse incomplete scans and omit private state. Optional artefact metadata is strict, bounded, display-only import context: supplied evidence labels never become inferred findings. Context clears on workspace change/restart. Generic bundles omit the manifest; only explicit review-pack export rebuilds safe metadata from included current content. Docs Site front matter takes priority over optional artefact hints.

Private content libraries merge supported browser JSON without replacing originals; templates open new tabs, snippets preserve one Undo and export profiles remain session choices. Browser Word migration exports original DOCX bytes for native validation/import. Appearance transfer uses a separate strict 64 KB JSON contract, bounded depth, duplicate/null/value rejection and optional-field merging. Imports populate private dialogue choices; Apply merges into current preferences without replacing paths or update consent. No browser-profile scanning or imported resource/font loading is introduced. See the [settings contract](settings-transfer-format.md).

Per-user self-contained Inno packaging uses distinct installation, state, mutex, uninstall and Open with identities. Uninstall preserves workspaces/state, default file associations are untouched and files-in-use handling does not force-close unsaved work. Package versions are immutable output directories. See [Inno AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm) and [non-administrative installation](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm).

Installer CI uses two preview versions from one source revision to exercise package replacement. It compares installed metadata, assembly informational version and uninstall registration with each requested package, and retains hashes of actual first-launch private state and workspace source across upgrade/removal/reinstallation. This tests replacement and preservation, not historical schema migration or production-signed updates. Save dialogue automation separately waits for the labelled enabled filename control within the existing deadline; window discovery alone does not establish child-control readiness. Failure evidence includes the owned dialogue and installed-app diagnostics.

Update checking and installation are separate user-controlled operations. Eligible GitHub metadata must match product, channel, version, architecture, Windows compatibility and official asset location. Signed manifests bind installer size/hash; Windows Authenticode/revocation and pinned publisher checks protect execution. The launcher waits for the exact parent, rechecks while holding a read lock and preserves session recovery. Production trust is intentionally unconfigured in this unsigned preview. Positive signed-upgrade certification remains external; [packaging and update details](update-and-packaging.md) define the contract.

Validation combines deterministic Core tests, real files/packages, native hidden-control/HWND checks, Windows UIA workflows and installer lifecycle runs. Foreground interaction is isolated from the user's desktop. The validation client uses a windowless MTA thread for UIA and a pumping STA dispatcher for clipboard/OLE objects, following [Microsoft threading guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading). Frozen bitmap clones preserve cross-thread pixels. The earlier combined STA client is a plausible source of the retained timeout, not a proven diagnosis. Failure screenshots/native stacks bypass UIA; no full heap/environment dump is requested. Existing assertions remain unchanged.

Import/export budgets count retained and expanded resources separately. DOCX relationships resolve to package-part URIs before image retention, with per-image, aggregate and count limits checked while reading. Export preflight counts every image/diagram/formula occurrence within the selected scope before serialisation; unique-resource caching alone does not bound output. HTML writes and DOCX/PDF streams reject excessive growth. Word shares image parts while preserving distinct drawing descriptions and IDs; PDF shares immutable image-source strings. Cancellation reaches traversal and writes, although MigraDoc rendering remains a synchronous dependency call. Modest-budget tests exercise limits without memory exhaustion.

The actual Windows signature boundary has a separate CI-only test path. A short-lived non-exportable certificate signs isolated apphost copies; Windows verification and exact publisher pinning are exercised independently of mocked trust. Its public certificate goes into the disposable runner's machine root store; the private key stays in CurrentUser\My. The script requires an elevated GitHub-hosted Windows runner, reports stages and has a three-minute CI limit. Certificate/private-key removal is checked and only JSON evidence is uploaded. It refuses local execution, leaves the build/embedded production policy unchanged and does not execute the signed fixtures. This development check does not replace production issuer, revocation, timestamp or signed-upgrade certification.

Autolink leaf nodes require explicit text handling: native controls, heading/plain-text extraction and Word/PDF export retain the original label. Native activation uses the existing reviewed navigation callback. A shared export URI check permits only HTTP, HTTPS and mailto, rejecting literal control characters before URI normalisation. PDF uses the dependency's supported URL hyperlinks, including per-line wrapped annotations; it never creates file-launch or active-scheme actions from unsupported references. Validation inspects real PDF annotations and selectable text without opening destinations. See [MigraDoc hyperlinks](https://docs.pdfsharp.net/MigraDoc/DOM/Contents/Hyperlinks.html).

PDF code blocks reuse the bounded bundled syntax preparation and light palette already used by native preview. Coloured runs remain selectable text; unknown or over-budget code retains complete plain text. MigraDoc's explicit space API preserves code indentation and repeated spaces, which ordinary text insertion drops at line starts. No source characters are replaced with non-breaking spaces. Actual PDF glyph colours, text positions and multi-page fallback content are checked. Word/HTML syntax colouring remains separate.

Detailed implementation contracts and original decision notes are preserved in the [architecture appendix](history/architecture-notes-2026-10-12.md). Current validation and explicit remaining limits are maintained in the other four native tracking documents.
