# Native architecture decisions

Workspace maps are read-only snapshots of explicitly opened folders and captured saved-file drafts. Core parsing produces typed documents and source-positioned links; partial catalogues, unreadable targets, missing sections and ambiguity remain distinct. Limits are 1,000 parsed documents, 2 Mi characters per document, 16 Mi aggregate characters and 10,000 links. Private native state is excluded, including refusal of a workspace inside that state. Native lists search/filter without source writes; source navigation rechecks the exact captured text. Diagrams use safe generated Mermaid labels with at most 60 documents/240 distinct connections and the existing frozen native drawing/export path. Full scanned lists remain available, while report tables include at most 2,000 links and use variable-length code spans to prevent supplied metadata becoming Markdown or automatic links. Building and drawing preparation run off the UI thread; cancellation completes before opening any result window.

Desktop wiki-link checks use WPF TextPattern children for hyperlink discovery, as ordinary document links already do. CI showed a rendered, visible wiki link that ordinary automation-tree queries could not find. The correction changes observation only; native navigation and source remain unchanged.

Save as uses the same wiki catalogue to retain known targets when the destination stays in an accessible workspace, preserving aliases and local section references. Cross-workspace document targets join the existing explicit uncopied-link confirmation; their files are never silently copied. First-save staging preserves ordinary and wiki links, and standalone Mermaid syntax is excluded from wiki rebasing.

Wiki links are dedicated source-aware Markdig containers, never URI schemes or executable HTML. Literal aliases and target spans survive parsing; code/HTML contexts and nested ordinary links cannot introduce native nested actions. A bounded catalogue resolves explicit paths before unique names and reports ambiguity. Native navigation revalidates the selected workspace and active source before opening. Completion stays outside code, including unfinished fences whose Markdig block span may cover only the opening line; original line positions establish their full source extent. Reviewed moves rewrite only target spans and skip standalone Mermaid node syntax. Workspace review shares current-draft/target budgets, and Docs Site resolves against included pages before removing temporary metadata. Other exports retain labels without app actions.

Optional artefact metadata is parsed only from ZIP import, against the exact supported document paths actually extracted. UTF-8/JSON depth, manifest size, display text and warning counts are bounded. Unknown fields, unsafe/missing paths and unsupported evidence labels cannot grant access or become inferred evidence. The raw manifest never enters workspace or recovery state. A native grouped reader filters immutable supplied records; context clears on workspace change/restart. Only explicit review-pack export rebuilds the versioned manifest from exported paths and current source. Generic bundles exclude it; Docs Site uses safe display hints after front matter and the existing artifactBundle JSON field, with literal text rendering and unchanged candidate wording.

Desktop validation retries the specific transient UIA COM observation timeout 0x80131505 inside its existing 20-second condition deadline. It does not replay the associated user action. The last observation exception is retained if the expected state remains unavailable. This follows a retained installed-app screenshot showing successful rich copy while its UIA status lookup timed out; unrelated COM errors still fail immediately.

The native user guide is reviewed Markdown embedded into Core at build time from docs/native/user-guide.md. Its twelve immutable topics use source-aware heading boundaries; bounded topic search reads bundled titles and body text without external access. F1 opens a separate modeless WPF guide with native selectable rendering and context-local Ctrl+F/Escape. Theme and high-contrast changes refresh its document, and no help content enters the workspace editor or session. The shared renderer explicitly uses left-aligned text and wrapping diagram actions to avoid stretched headings and clipped controls in narrow panes observed during desktop screenshot review.

Native settings edit a typed appearance-only snapshot. Apply merges it into the latest UserPreferences under the existing persistence gate, preserving concurrent update consent/check timestamps, recent paths and window placement. Optional editor/preview records retain compatibility with earlier native JSON; supported values are bounded and invalid saved state follows the existing retained-copy/backup path. The modal MVVM editor keeps defaults and cancellations private, reports failed writes inline, and blocks closing during its atomic save. Applying font/wrap/indentation changes configures the existing AvalonEdit control without replacing its document; preview zoom uses WPF's native scale and does not regenerate exports or unchanged-theme preview content.

Native preview navigation is deferred until WPF layout can locate the requested TextPointer. It retains the expected FlowDocument, rejects pointers from another document, resolves expanded content, then adjusts the viewer's scroll offset from the actual character rectangle. This replaces immediate Run.BringIntoView calls that selected offscreen content without scrolling. Find, formula search, outline, local fragments and history share the same path; source and selection remain unchanged.

Maths uses pinned WpfMath/XamlMath.Shared 2.1.0 with bundled fonts and frozen WPF DrawingImages, prepared on the existing STA path. A small inline parser matches the web dollar/parenthesis contract; standard Markdig math nodes retain original spans and normal HTML fallback. Bounded source adaptation corrects the engine's square-bracket pmatrix convention to standard round brackets and supports common matrix/cases/aligned environments without editing Markdown. Native preparation bounds source, commands, nesting, cells, drawing dimensions and aggregate work; a 128-entry cache reuses frozen drawings. Unsupported formulae stay visible as source. Rich exports use explicit display dimensions with 3× PNGs, while source copy and plain preview copy retain LaTeX. The package includes upstream font notices and MIT/OFL licence texts. References: [XAML-Math v2.1.0](https://github.com/ForNeVeR/xaml-math/tree/v2.1.0) and its [matrix conventions](https://github.com/ForNeVeR/xaml-math/blob/v2.1.0/docs/matrices.md).

Details use a bounded Markdig block parser that recognises complete passive wrappers and lets Markdig parse their children at original source offsets. Fences, comments and raw text blocks cannot close a recognised wrapper. The native renderer holds child WPF blocks behind accessible expanders; source navigation opens only containing sections, while preview search reveals all sections before finding text. No imported HTML attributes reach controls. Word, PDF and rich clipboard flatten closed sections into complete content; standalone HTML and Docs Site retain semantic details/summary elements. The editor computes a validated Core edit off-thread, preserves existing body bytes for summary-only changes and applies one guarded AvalonEdit undo group.

Built-in content is compiled as reviewed JSON data derived from the existing web registry by a development-only Node script. Installed generation uses bounded, one-pass C# field substitution; inserted field text is never interpreted again as a token. Suggested filenames use bounded portable slugs, and the existing library contract checks generated Unicode/content. Explicit native wording adaptations are asserted by the generator, and native CI detects catalogue drift. The WPF chooser retains field edits while filtering, previews source and routes template/snippet application through the same data-preserving paths as the personal library. Mermaid examples retain editable source; every complete template and contextual snippet is validated through the native renderer in both themes.

Native library templates open new unsaved tabs and materialise validated embedded images before attaching them; existing tabs are retained. Snippets capture required external reference definitions and apply one source edit with complete Undo/Redo. Library file operations and source preparation run off the UI thread, with fingerprint conflicts and cancellation feedback. Named standalone Mermaid drafts use a private virtual .mmd path for native preview/export without treating imported names as filesystem authority. Export profiles are session state, separate from general preferences; users explicitly save reusable profiles to the library. Azure DevOps bundle conversion uses bounded input and source-line edits, preserves non-diagram content/encodings and leaves workspace files untouched. Fluent theme resources are tracked per owning ResourceDictionary so independent native surfaces receive their requested styles even when the theme name is unchanged.

Content-library interchange uses the existing lens-docs-studio-library-1.0 JSON contract. It does not inspect browser profiles or infer file/network access from imported metadata. Version/type/duplicate-property and UTF-8/count/aggregate bounds are checked before persistence. Imports merge with active and archived records, retain existing content, reassign conflicting identifiers and report already-present entries. Native state uses fingerprint-checked recovery writes; malformed state remains untouched. Reusable Markdown embeds validated local raster data while preserving diagram source; applying it materialises independent native assets before editor changes. Export preparation can skip diagram rendering for this purpose; normal document/clipboard export defaults are unchanged. User-facing library and profile integration remains work in progress.

The Word template library stores prepared formatting and versioned, bounded metadata under private native state. GUID-derived paths are independent of imported names/metadata; source paths are not retained. Import publishes a durable staging directory atomically, rename uses fingerprint-checked recovery writes, and archive/restore moves the existing entry without deleting its bytes. An exclusive file lock prevents cross-instance mutation. Stored size/hash checks detect damage, but do not authorise content: every selected or copied template passes package extraction again. Corrupt entries are retained with warnings. Library entries persist; applied formatting remains an explicit session choice. Generic name prompts now have context-specific accessible names and help instead of describing every value as a workspace path.

Word templates are now extracted into a fresh package. Only supported styles, numbering, theme, selected settings, table formatting and the final section's effective header/footer references survive; referenced static images and ordinary hyperlinks are copied with their relationship IDs. Original body content, comments, custom XML, unrelated media and package properties do not cross into exports. First/even/default header/footer types and prior-section inheritance are retained, without merging source section bodies. Retained markup rejects active objects, direct resource/action attributes, tracked changes/comments and fields other than page/section/date/time. ZIP input is bounded by 32 MB compressed/per-entry, 128 MB expanded and 1,024 entries, with actual-byte/checksum validation. Prepared structure is validated against the Open XML Microsoft 365 schema before selection. Cancellation leaves the previously selected template intact. Generated numbering/drawing IDs use free IDs rather than overflowing the largest retained value.

Word semantic style resolution matches normalised template IDs/names only within the required paragraph/table type. H1–H6 keep their actual heading levels; generated fallback headings include Word outline levels and readable formatting. Body, code, quote, caption and table aliases follow the existing template contract. Existing style XML and table prototype properties remain unchanged; fallback IDs avoid collisions with incompatible styles. Quote context flows through nested list paragraphs without removing numbering. Package extraction and template management remain separate work.

The image figure editor operates on an existing top-level image or recognised figure. It retains the destination/title and converts only that source block, leaving shared reference definitions and surrounding text intact. A bounded worker parse and current-document/selection checks precede the native dialogue; source is checked again before one AvalonEdit undo group is applied with the viewport retained. This reuses existing safe image insertion/persistence instead of creating a separate path that could publish an unpersisted asset reference. Inline/list/quote image conversion remains deliberately unsupported until its surrounding syntax can be retained.

Recognised image figures become typed blocks containing an explicitly HTML-origin image node. A bounded scanner accepts the existing passive helper structure and retains exact original image/attribute spans; it rejects extra attributes, duplicate destinations and nested caption markup. Shared image preparation, asset transfer and auditing can therefore resolve the image, while rewrites encode HTML attribute values and leave every other source character intact. Native WPF captions are selectable. Exporters generate their own passive figure/caption output. Markdown clipboard HTML marks only the image's syntax kind; imported markers remain untrusted and never authorise retrieval. Unknown figures retain their raw HTML tree and conservative asset audit treatment.

Workspace file notifications update conflict flags separately from the file tree. Creation, deletion and rename trigger a 250 ms debounce and cancellable bounded enumeration on a worker; results are accepted only for the current watcher/workspace. Observable native tree nodes are reconciled by path so surviving controls keep expansion and selection. Refresh does not open, reload or save documents. Private native state is excluded, and watcher errors remain visible. This corrects the missing automatic tree refresh exposed by desktop review validation.

Workspace document review composes the same current-buffer analysis with read-only target checks on a worker. Paths resolve inside the document's existing workspace and exclude private native state; external URLs and non-document assets are never fetched. Captured open buffers override saved target text, including explicit links back to the current source. File reads use the guarded document store; missing targets, unreadable/unsafe targets and incomplete coverage remain distinct. Limits are 100 distinct targets, 4 Mi characters per target and 16 Mi aggregate target characters, counting oversized drafts before stopping. Target anchor sets are cached for one review only. The window revalidates captured source/tab identities and text before showing or navigating results. If the workspace cannot be opened, current-buffer review remains available with explicit incomplete-link feedback.

Pipe-table review reads original source lines because the parsed table can pad or discard cells. It checks separator syntax and header/separator/body widths without allocating a string per cell. Escapes, optional outer delimiters and nested quote/list prefixes are accounted for; front matter, fenced/indented code and raw HTML blocks are excluded using parser spans. Findings retain complete original row locations, including prefixes and CRLF boundaries. Virtualised review accessibility is checked after scrolling each note into view; off-screen items are not assumed to have realised automation children.

Current-document review uses the Markdig tree on a worker, preserving original UTF-16 source offsets and CRLF/Unicode locations. Markdown headings, reference images and same-document fragments are structural checks; literal prose receives advisory spelling/marker checks. Fenced/indented/inline code, URL destinations, front matter and unsupported HTML are excluded from prose checking. Metrics count decoded visible inline text across formatting boundaries and use the existing 220-word reading estimate. Source is limited to 4 Mi characters, depth to 64 and retained notes to 2,000, with explicit limited-result feedback. A virtualised native list supplies accessible messages and line/column labels; selecting a note revalidates the captured document, restores editor focus and records navigation history. Nothing is rewritten, persisted or fetched. Raw HTML validation remains separate work rather than inferred clean results.

Table CSV export parses captured source on a worker and resolves the same exact table span as copying. A bounded text walk retains decoded entities, passive labels, code, link labels and image alt text without opening any resource. Unknown HTML remains literal, matching native preview. Cells use CSV quote doubling, embedded LF, CRLF rows and UTF-8 without a BOM; values are not prefixed or interpreted. This preserves the web CSV data contract while retaining image descriptions and empty rows. Spreadsheet type inference remains a destination concern; rich Excel copying has separate literal-cell metadata. The native Save dialogue suggests the table's document order (Windows may hide its selected extension), and the existing export writer protects replacements, cancellation and recovery. Limits are 4 Mi source characters, 100,000 cells, depth 64 and 16 Mi output bytes.

Table copying captures the displayed document identity, source and table span. The window refuses an outdated preview before queuing preparation. A validated table selection resolves against the complete parsed document, retaining reference definitions while limiting image/diagram preparation and HTML rendering to that table. The shared clipboard exporter applies existing literal-cell metadata and Unicode fallback; rendering does not detach or mutate the syntax tree. Clipboard sequence protection remains in force. Context menus stay outside document/export text. CSV uses the independent resource-free text contract described above.

Markdown editor highlighting shares the preview's fixed readable palette. It runs before AvalonEdit's selection transformer, so syntax colours cannot override selected text. The window reapplies theme/selection resources and redraws existing lines on user or Windows theme changes; high contrast retains system text/highlight colours. Per-line scans are bounded to 4,096 characters, 512 matches, an 8 ms between-match budget and a 25 ms regex timeout. Matches are collected before applying styles, so a failed/limited scan leaves consistent inherited text. Theme changes never replace the editor document or selection.

Native colour validation inspects real control runs and WPF text providers in hidden native hosts, without requiring foreground keyboard access. Desktop checks exercise actual theme menus separately. WPF's numeric foreground attribute is verified as RGB; tests must not assume Win32 BGR ordering.

Code syntax preparation runs on the existing preview worker using only [AvalonEdit's bundled definitions](https://github.com/icsharpcode/AvalonEdit/tree/master/ICSharpCode.AvalonEdit/Highlighting/Resources). The fourteen allowlisted language families cannot load definitions or paths from document text. Copied rule graphs preserve nested state and add a 25 ms regex match timeout without modifying shared definitions. Preparation bounds blocks to 32 Ki characters, lines to 4,096 characters, coloured spans to 1,024 per block/16,384 per document and aggregate text to 1 Mi characters. A 250 ms text-processing budget is checked between lines; initial trusted-definition loading is separate. Native runs use fixed contrast-tested palettes and retain exact source/selection text. Unknown languages, timed-out/oversized blocks and stale plans remain plain; high contrast inherits system colours. Syntax colouring is a preview concern and does not rewrite source or exports.

Editing plans live in Core and describe one source replacement plus the resulting selection. A small AvalonEdit service applies each plan as one undo group, restores scroll position and focuses the editor. Inline actions toggle selected/adjacent delimiters, including nested bold/italic; line actions retain indentation and line endings. Mixed list conversion preserves existing task states. Code fences grow around embedded backticks, templates retain selected text, and block padding inspects only neighbouring source characters. Formatting does not write files or alter read-only documents.

Markdown emphasis and ordered-list starts share a small semantic mapping across native preview and exporters. WPF callouts use labelled Sections with neutral surfaces and a compact accent border. WPF lists starting at zero use explicit markers because the native List starting index requires a positive value. Pipe-table columns use their source order when Markdig does not set a cell index. Soft source lines become spaces; hard breaks remain breaks. DOCX preserves independent strike, scripts, insertion and highlight properties. MigraDoc lacks strikeout support, so PDF retains explicit deletion markers; PDF strikeout/highlight fidelity remains incomplete.

Copy Markdown with images uses parser source spans to replace image destinations and complete Mermaid blocks. Reference images expand at each occurrence without rewriting shared definitions or ordinary links. Unicode text retains source; CF_HTML carries escaped literal text and ordered PNG image elements without semantic document tags. Remote references are not fetched, unfinished fences stay literal, and preparation has source/image/payload limits. The source-carrier marker is an untrusted format hint. Automatic Markdown paste extracts bounded raster data, then native validation and persistence complete before one anchored editor replacement; forced text remains literal.

Recognised status and keyboard HTML snippets are converted to bounded typed inline nodes after Markdown parsing. The converter validates an inert fragment and derives visible text from the existing Markdown tree; links, images and unknown structures remain untouched. Native rendering uses selectable WPF spans with fixed neutral styling and source references. HTML, Word and PDF exporters emit fixed text semantics without copying imported attributes. Original Markdown remains authoritative, including for source clipboard output. Entity nodes are explicitly decoded by native text and document exporters.

Named anchors recognise the existing span/id/data-doc-anchor contract, including empty labels. Heading and anchor identifiers are made unique in source order and reused by preview, the link picker and exporters; source Markdown is unchanged. WPF spans retain exact source destinations without executing HTML. Word uses generated bookmark names/identifiers that avoid retained template bookmarks; PDF uses named destinations, including across pages. Only same-document fragments become Word/PDF internal links. Editing a label keeps the identifier so incoming links remain valid; identifier rename/review is separate work. The native document-link picker captures current tab text before opening, so unsaved targets are available without writing files.

Editor context commands explicitly target AvalonEdit's TextArea when the menu opens, avoiding focus-dependent routing through the popup or inactive search controls. A placement-target binding left standard commands disabled in desktop CI; actual routed Select all/Undo checks now cover the correction. Formatting respects document availability and read-only state. Code context menus belong to WPF paragraphs and dispatch plain Unicode text only after an explicit action. Copying Markdown includes the opening line's indentation or quote/list context; code copying uses parsed code lines. Both are bounded before dispatch, remain separate from source/export content and use the existing busy-clipboard feedback. Table-specific rich copying shares the validated source selection described above.

Progress figures use a separate bounded block mapping for the established label/value/progress structure. Only finite numeric values and a fixed colour set reach WPF; imported event handlers, styles and accessibility overrides are discarded. A selectable label accompanies a native ProgressBar with a read-only UI Automation range. DOCX/PDF use fixed coloured bar segments and percentage labels; HTML uses a semantic progress element. The native dialogue captures source/selection, parses off the UI thread and revalidates before replacing source. Inserting/editing uses the same portable snippet and one AvalonEdit undo group. Invalid structures remain literal instead of inventing progress values.

Mermaid completion uses a pure Core catalogue/context service and AvalonEdit's native completion window. Context respects standard and Azure DevOps fences, comments and quoted labels; acceptance revalidates the current document and replaces a complete token with preserved indentation/line endings. Automatic scans stop at 256 Ki characters and explicit Ctrl+Space at 4 Mi characters, avoiding unrestricted synchronous scans while typing. Native completion closes on document/focus changes and protects read-only editors and active selections. Wikilink completion is separate remaining work.

Front matter follows the web product's flat allowlisted contract, not general YAML execution. A bounded header is replaced with equal-length blank lines for parsing, preserving original source spans and clipboard text. Metadata provides Docs Site title, description, order, tags, draft and navigation group; visible document headings are the title fallback.

Docs Site export enumerates an explicitly opened workspace, excludes private state and refuses incomplete enumeration. It captures edits to saved documents, prepares images/diagrams on the native STA worker and creates a guarded ZIP. Limits cover 1,000 pages, 32 MB per source, 64 MB aggregate source and 256 MB output. Rendered HTML is sanitised; links resolve only to packaged document identities or explicit external HTTP/mail links. Unresolved local links retain visible labels and report warnings. Fixed JavaScript/CSS templates are embedded export resources; the desktop app never executes them and requires no Node or browser runtime. A separate browser suite validates the destination artifact without adding .NET to web publishing.

Docs Site search indexes page metadata/introductory text separately from each heading section, including nested headings, code and tables. Heading targets are unique within each page. Iterative traversal preserves inline word boundaries; aggregate entry/byte budgets are checked before serialisation. The static client ranks section matches, builds highlighted snippets with text nodes and routes to the encoded heading with keyboard focus and browser history. Searches yield between batches and obsolete results are cancelled; overlong queries get explicit feedback rather than silently dropping terms.

Markdown Bundle export uses the same bounded workspace listing as other native folder operations, with an explicit private-state exclusion supplied by the window. Only that configured path is excluded; ordinary similarly named documentation is retained. Equal/descendant paths are normalised consistently, including trailing separators. Incomplete listings fail before any destination write. Saved entries use bounded read streams that deny concurrent writers, and draft limits apply to encoded UTF-8 bytes. Generic bundles still omit the optional artefact manifest and preserve original source files. Import accounts for actual returned bytes and checks declared length and [entry CRC32](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.ziparchiveentry.crc32?view=net-10.0) before staging content. Microsoft System.IO.Hashing is pinned for the checksum calculation; CRC is a corruption check, not an authenticity boundary.

1. Separate src/native solution: .NET 10, WPF, AvalonEdit, CommunityToolkit.Mvvm. Existing web and WinUI/WebView2 shell remain independently buildable.
2. Core owns portable documents, source-aware Markdig parsing, filesystem safety, imports/exports, preferences, recovery and update eligibility. Native owns WPF rendering and Windows integration. Dependency injection through constructors.
3. Mermaider is the first browser-free Mermaid candidate; native SVG compatibility is a gate, not assumed from valid XML. Reference: https://github.com/nullean/mermaider. No browser fallback.
4. Open XML SDK for DOCX; preserve template package parts and verify relationships. PDFsharp/MigraDoc provides local WPF-based PDF generation, PdfPig extracts PDF text, and AngleSharp parses HTML without a network browsing context. These are open-source packages pinned in lock files. Full template fidelity and tagged PDF remain validation work.
5. Native identity: LensDocsStudio.Native, isolated state and installation. Self-contained Inno Setup package; no static web assets in runtime.
6. Updates require explicit product/channel/architecture/OS/version metadata, integrity and publisher trust. Unsigned internal builds may link to releases but must not execute untrusted downloads.
7. develop omits newer main work on portable images, exact document navigation and full Word template packages. Both functional contracts are in scope; no merge of main into develop is implied.

Candidate library documentation and versions are verified against upstream repositories and NuGet. Pinned lock files will record restored dependencies.

Rendered copy shares the HTML export model, sanitises generated attributes and embeds native PNG images/diagrams without local source paths. Windows CF_HTML offsets count UTF-8 bytes, following the [Microsoft clipboard format specification](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format). Unicode text provides semantic paragraphs, task states and tab-separated table cells. Preparation runs on a cancellable STA worker with source/image budgets; the final write refuses an intervening clipboard change. Destination application fidelity requires separate validation.

HTML file import and formatted paste share an inert AngleSharp-to-Markdown converter. Literal punctuation is escaped; nested lists, code delimiters and rectangular table positions are preserved. Merged cells produce a warning and bounded expansion. Embedded raster bytes are deduplicated and validated/persisted through the native image service before replacing the editor selection. Linked images remain references without retrieval. Paste Special offers table, text, code, quote, HTML, list, checklist, numbered list and Mermaid; Ctrl+Shift+V forces literal text. Rich clipboard HTML takes precedence over a fallback bitmap, while Markdown-like Unicode text retains its source form. Source anchors and a single undoable replacement protect edits made during preparation.

Rendered clipboard tables carry fixed Excel string metadata and text number formatting after sanitisation. An actual Excel destination check found that an unmarked =1+1 cell became a formula; the corrected carrier preserves literal values and leading zeroes. Unicode fallback text remains unchanged. Optional --office validation uses new hidden Office instances and disposable documents, refuses an existing Word session and verifies a separate Excel process before creating a workbook. It closes only owned instances and restores the clipboard only when its sequence still belongs to the check. Office is not required by the product or standard CI.

Native SVG parsing runs on an STA worker; frozen drawings can safely cross to the UI thread. Bounded caches retain unchanged diagrams without retaining full document trees. SVG input is checked for active elements, external resource references and CSS escapes before SharpVectors receives it. Local fragment paint definitions remain supported. FlowDocument construction is still on the UI thread and large-document rendering remains an open performance item.

Raster preview preparation now shares the serial cancellable preview worker. It reads and hashes workspace-bounded files, decodes frozen pixels, deduplicates identical images and retains at most 128 MB of cached decoded data across 256 entries. Each preparation has a 256 MB decoded/source budget and 512 distinct image references; individual raster decoding also checks pixel memory before allocation. Content hashes detect edits even with preserved timestamps. The native layout renderer receives prepared pixels and performs no image file reads. Rejected resources produce visible placeholders/warnings; source remains untouched. Full FlowDocument construction and layout still need large-document optimisation.

WPF document construction now yields to the dispatcher after up to 32 top-level blocks or an approximately 8 ms batch. Native objects retain UI-thread ownership; input and cancellation run between batches. The old preview remains visible, and a result is committed only if its document and cancellation token are still current. Synchronous rendering remains available to export/validation callers. This avoids partial-preview publication but does not virtualise individual blocks or eliminate final viewer layout costs; those remain measured optimisation work.

Use .NET 10's built-in WPF Fluent resource dictionaries rather than introducing a separate UI framework. Apply Windows high-contrast system colours, expose native automation names and retain per-monitor DPI metadata. Window placement uses the Windows placement API so removed monitors can be reconciled by the operating system.

Unsaved-document images live in a per-document draft directory under native state; recovery records retain that location. Save as writes any copied image bytes before committing rewritten Markdown. Cancelled saves clean up completed, unchanged asset copies; uncertain files and prior draft assets remain available for recovery. Markdig URL spans preserve unrelated Markdown and reference-style links. AvalonEdit anchors follow pending insertions and avoid deleting intervening edits.

Remote image retrieval is an explicit Insert command, with HTTPS-only redirects, no embedded credentials or cookies, a 32 MB streamed limit and a cancellable 45-second deadline. Downloaded bytes pass through the same native raster decoder and PNG persistence as local images. Preview, import and export share dimension validation before creating the pixel cache; remote Markdown image references never trigger automatic downloads.

The image manager audits documentation references and open saved-file drafts; it does not claim to scan arbitrary application code or metadata. Front matter, CSS, responsive image references and unreadable documents make usage incomplete. Raw HTML references are counted but require manual editing before rename. Native state is excluded and cannot be mutated through this workflow. Renaming saves open workspace edits, reviews precise Markdown URL changes, revalidates the plan, retains original image bytes and text journals, then performs guarded writes with rollback. Removal requires a complete, unreferenced assessment and an independently verified snapshot before Windows recycling. Image snapshots recover through the existing draft/Save as flow, with no automatic source-path replay.

WPF exposes FlowDocument hyperlinks through UI Automation TextPattern ranges; the desktop harness uses that interface rather than assuming hyperlinks always appear in the initial control tree. Tabs, file tree entries and outline items have explicit readable automation names.

Filesystem moves require a reviewable plan based on source snapshots. The operation refuses existing destinations and external changes, retains a durable record of original/planned text, then guards each write and reverses completed work on failure. Recovery records are interpreted as text drafts only; untrusted journal paths never authorise replay. A successfully persisted recovery session permits archiving the original journal as reviewed, without deleting it. Folder and case-only rename semantics are deferred until separately validated.

Document deletion preserves saved source and unsaved text as separate immutable snapshots before removing the file. A unique sibling holding directory lets the service inspect the exact moved file before asking the Windows shell to recycle it; cancellation/failure rolls it back without replacing an external file. An interrupted holding file remains visible in the workspace. Snapshot recovery is the application's supported restore route because Windows recycling availability and the shell's original-location record depend on the filesystem. Native snapshot reads never replay recorded source paths. Exact source is retained alongside a portable image copy where available; missing images produce explicit warnings without suppressing text recovery.

Installer files-in-use behaviour uses an application mutex and disables forced closure/restart. Per-user Open with registration does not take over default extensions. See [Inno AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm) and [non-administrative installation](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm). No uninstaller action removes application state or workspaces.
