# Native architecture decisions

Editing plans live in Core and describe one source replacement plus the resulting selection. A small AvalonEdit service applies each plan as one undo group, restores scroll position and focuses the editor. Inline actions toggle selected/adjacent delimiters, including nested bold/italic; line actions retain indentation and line endings. Mixed list conversion preserves existing task states. Code fences grow around embedded backticks, templates retain selected text, and block padding inspects only neighbouring source characters. Formatting does not write files or alter read-only documents.

Markdown emphasis and ordered-list starts share a small semantic mapping across native preview and exporters. WPF callouts use labelled Sections with neutral surfaces and a compact accent border. WPF lists starting at zero use explicit markers because the native List starting index requires a positive value. Pipe-table columns use their source order when Markdig does not set a cell index. Soft source lines become spaces; hard breaks remain breaks. DOCX preserves independent strike, scripts, insertion and highlight properties. MigraDoc lacks strikeout support, so PDF retains explicit deletion markers; PDF strikeout/highlight fidelity remains incomplete.

Copy Markdown with images uses parser source spans to replace image destinations and complete Mermaid blocks. Reference images expand at each occurrence without rewriting shared definitions or ordinary links. Unicode text retains source; CF_HTML carries escaped literal text and ordered PNG image elements without semantic document tags. Remote references are not fetched, unfinished fences stay literal, and preparation has source/image/payload limits. The source-carrier marker is an untrusted format hint. Automatic Markdown paste extracts bounded raster data, then native validation and persistence complete before one anchored editor replacement; forced text remains literal.

Baseline: develop 2cc3b5680958c9c553dad23856e6010c158fccd7, inspected 11 October 2026. The original checkout remains on main 0d100cc29dde2ba80755fb1e8af60ffd9d006b16 with an unrelated untracked attachment directory preserved.

1. Separate src/native solution: .NET 10, WPF, AvalonEdit, CommunityToolkit.Mvvm. Existing web and WinUI/WebView2 shell remain independently buildable.
2. Core owns portable documents, source-aware Markdig parsing, filesystem safety, imports/exports, preferences, recovery and update eligibility. Native owns WPF rendering and Windows integration. Dependency injection through constructors.
3. Mermaider is the first browser-free Mermaid candidate; native SVG compatibility is a gate, not assumed from valid XML. Reference: https://github.com/nullean/mermaider. No browser fallback.
4. Open XML SDK for DOCX; preserve template package parts and verify relationships. PDFsharp/MigraDoc provides local WPF-based PDF generation, PdfPig extracts PDF text, and AngleSharp parses HTML without a network browsing context. These are open-source packages pinned in lock files. Full template fidelity and tagged PDF remain validation work.
5. Native identity: LensDocsStudio.Native, isolated state and installation. Self-contained Inno Setup package; no static web assets in runtime.
6. Updates require explicit product/channel/architecture/OS/version metadata, integrity and publisher trust. Unsigned internal builds may link to releases but must not execute untrusted downloads.
7. develop omits newer main work on portable images, exact document navigation and full Word template packages. Both functional contracts are in scope; no merge of main into develop is implied.

Candidate library documentation and versions are verified against upstream repositories and NuGet. Pinned lock files will record restored dependencies.

Rendered copy shares the HTML export model, sanitises generated attributes and embeds native PNG images/diagrams without local source paths. Windows CF_HTML offsets count UTF-8 bytes, following the [Microsoft clipboard format specification](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format). Unicode text provides semantic paragraphs, task states and tab-separated table cells. Preparation runs on a cancellable STA worker with source/image budgets; the final write refuses an intervening clipboard change. Destination application fidelity requires separate validation.

HTML file import and formatted paste share an inert AngleSharp-to-Markdown converter. Literal punctuation is escaped; nested lists, code delimiters and rectangular table positions are preserved. Merged cells produce a warning and bounded expansion. Embedded raster bytes are deduplicated and validated/persisted through the native image service before replacing the editor selection. Linked images remain references without retrieval. Paste Special offers table, text, code, quote, HTML, list, checklist, numbered list and Mermaid; Ctrl+Shift+V forces literal text. Rich clipboard HTML takes precedence over a fallback bitmap, while Markdown-like Unicode text retains its source form. Source anchors and a single undoable replacement protect edits made during preparation.

Rendered clipboard tables carry fixed Excel string metadata and text number formatting after sanitisation. An actual Excel destination check found that an unmarked =1+1 cell became a formula; the corrected carrier preserves literal values and leading zeroes. Unicode fallback text remains unchanged. Optional --office validation uses new hidden Office instances and disposable documents, refuses an existing Word session and verifies a separate Excel process before creating a workbook. It closes only owned instances and restores the clipboard only when its sequence still belongs to the check. Office is not required by the product or standard CI.

Native SVG parsing runs on an STA worker; frozen drawings can safely cross to the UI thread. Bounded caches retain unchanged diagrams without retaining full document trees. SVG input is checked for active elements, external resource references and CSS escapes before SharpVectors receives it. Local fragment paint definitions remain supported. FlowDocument construction is still on the UI thread and large-document rendering remains an open performance item.

Raster preview preparation now shares the serial cancellable preview worker. It reads and hashes workspace-bounded files, decodes frozen pixels, deduplicates identical images and retains at most 128 MB of cached decoded data across 256 entries. Each preparation has a 256 MB decoded/source budget and 512 distinct image references; individual raster decoding also checks pixel memory before allocation. Content hashes detect edits even with preserved timestamps. The native layout renderer receives prepared pixels and performs no image file reads. Rejected resources produce visible placeholders/warnings; source remains untouched. Full FlowDocument construction and layout still need large-document optimisation.

Use .NET 10's built-in WPF Fluent resource dictionaries rather than introducing a separate UI framework. Apply Windows high-contrast system colours, expose native automation names and retain per-monitor DPI metadata. Window placement uses the Windows placement API so removed monitors can be reconciled by the operating system.

Unsaved-document images live in a per-document draft directory under native state; recovery records retain that location. Save as writes any copied image bytes before committing rewritten Markdown. Cancelled saves clean up completed, unchanged asset copies; uncertain files and prior draft assets remain available for recovery. Markdig URL spans preserve unrelated Markdown and reference-style links. AvalonEdit anchors follow pending insertions and avoid deleting intervening edits.

Remote image retrieval is an explicit Insert command, with HTTPS-only redirects, no embedded credentials or cookies, a 32 MB streamed limit and a cancellable 45-second deadline. Downloaded bytes pass through the same native raster decoder and PNG persistence as local images. Preview, import and export share dimension validation before creating the pixel cache; remote Markdown image references never trigger automatic downloads.

The image manager audits documentation references and open saved-file drafts; it does not claim to scan arbitrary application code or metadata. Front matter, CSS, responsive image references and unreadable documents make usage incomplete. Raw HTML references are counted but require manual editing before rename. Native state is excluded and cannot be mutated through this workflow. Renaming saves open workspace edits, reviews precise Markdown URL changes, revalidates the plan, retains original image bytes and text journals, then performs guarded writes with rollback. Removal requires a complete, unreferenced assessment and an independently verified snapshot before Windows recycling. Image snapshots recover through the existing draft/Save as flow, with no automatic source-path replay.

WPF exposes FlowDocument hyperlinks through UI Automation TextPattern ranges; the desktop harness uses that interface rather than assuming hyperlinks always appear in the initial control tree. Tabs, file tree entries and outline items have explicit readable automation names.

Filesystem moves require a reviewable plan based on source snapshots. The operation refuses existing destinations and external changes, retains a durable record of original/planned text, then guards each write and reverses completed work on failure. Recovery records are interpreted as text drafts only; untrusted journal paths never authorise replay. A successfully persisted recovery session permits archiving the original journal as reviewed, without deleting it. Folder and case-only rename semantics are deferred until separately validated.

Document deletion preserves saved source and unsaved text as separate immutable snapshots before removing the file. A unique sibling holding directory lets the service inspect the exact moved file before asking the Windows shell to recycle it; cancellation/failure rolls it back without replacing an external file. An interrupted holding file remains visible in the workspace. Snapshot recovery is the application's supported restore route because Windows recycling availability and the shell's original-location record depend on the filesystem. Native snapshot reads never replay recorded source paths. Exact source is retained alongside a portable image copy where available; missing images produce explicit warnings without suppressing text recovery.

Installer files-in-use behaviour uses an application mutex and disables forced closure/restart. Per-user Open with registration does not take over default extensions. See [Inno AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm) and [non-administrative installation](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm). No uninstaller action removes application state or workspaces.
