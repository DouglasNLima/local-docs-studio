# Accepted native improvements consolidation

The 19 October 2026 product decision accepts the bounded production changes in
PRs [#36](https://github.com/DouglasNLima/local-docs-studio/pull/36) and
[#37](https://github.com/DouglasNLima/local-docs-studio/pull/37). It ends the active
Continuous performance investigation and returns priority to native Mermaid editing.
The PR delivery receipt records actual integration SHAs, post-integration checks,
package versions, artefact links and hashes. Earlier receipts keep their original
source identities and do not certify the combined develop revision.

## Accepted application behaviour

- Five editors share consistent toolbars, full-name navigation, persistent
  inspector context, adjustable source panels and improved viewport/focus behaviour.
- Immutable canonical drawing conversion reuse remains bounded to eight entries
  and two million source/prepared-SVG characters. The measured 85–94% warm-median
  gains are repeat-presentation observations. Cold results remain mixed; retained
  memory limits and the unsuccessful dense ER resource diagnostic remain open.
- Stock Continuous retains table validation batching, adjacent-text coalescing,
  indexed viewport/source anchors with exhaustive fallback, owner-local palettes
  and stable brushes, selection retention and source/version/appearance guards.
- Existing semantic, safety, accessibility, export, workspace, recovery, lifecycle
  and resource protections remain applicable. No renderer or runtime was upgraded.

The original #37 250 ms goal is **INCOMPLETE**. Failed controlled samples and long
stock formatting/Input gaps remain failures. The original `.749` first-launch
incident is **UNRESOLVED**; later successful lifecycle runs establish no cause or
correction. Diagnostic segmentation and private-framework tools remain outside
the application solution and package path; they do not activate in ordinary use.

## Verification and preview contract

Final acceptance runs at the actual integrated develop revision. Native build/Core,
rendering/corpus/export, save/recovery/workspace, five-family normal/actual High
Contrast and installed authoring, browser/static and package lifecycle checks retain
their assertions and fixture bytes. The manual consolidation workflow adds the
existing focused literal/selection/anchor/theme and visible Continuous correctness
routes without starting another comparative timing investigation. Historical red
performance gates remain red; successful product checks do not override them.

The ordinary `Build-NativePackage.ps1` path produces fresh unsigned, self-contained
Windows x64 installer/portable pairs from clean committed source. The two versions
in one native workflow are a source-identical synthetic upgrade, not an actual
historical upgrade. Branch-conditioned historical jobs remain explicitly skipped.
Installers and actual OS appearance mutations run only on disposable authorised
Windows runners. Independent downloaded-package inspection executes no installer
on the ordinary desktop. No SDK-free clean-Windows, physical screen-reader,
higher-DPI, `.749` or production-trust certification is inferred. No public release,
tag movement, signing, updater publication or association change is authorised.

## Next Mermaid editor goal

Existing visual editors: **Flowchart, Sequence, State, ER and Class**.

The locked native dependency is **Mermaider 0.15.1**, package source commit
`71b64845570d633a94d29e85579c0a02786fece8`. Its packaged README documents these
other renderer families: Pie, Quadrant, Timeline, GitGraph, Radar, Treemap, Venn,
Mind map, Gantt, User Journey, C4, Sankey, XY, Requirement, Packet, Kanban,
Architecture, Block and TreeView. This is the pinned engine's inventory, not a
claim of complete native adapter/export or visual-editor certification for each.
Repository compatibility fixtures exercise Gantt, Pie and Mind map; the built-in
catalogue also exercises Journey and Timeline. Native rendering has no browser
fallback. See [compatibility and bounded corpus results](diagram-compatibility.md).

Recommend **Gantt** next: it supports useful documentation delivery/review plans and
already has native compatibility and built-in catalogue examples. First scope:
source-preserving title and section names, task labels, explicit ISO dates and
simple day durations; add/remove/reorder simple tasks through a keyboard-accessible
list and inspector, using canonical rendering. Preserve comments/Unicode/line
endings and protect unsupported dependencies/directives. Include private Undo/Redo,
one-step Apply, Cancel, owner/version conflicts and Save/reopen. Dependency editing,
calendar rules and drag rescheduling need a later explicit scope. This is a separate
goal and has no dependency on #38.
